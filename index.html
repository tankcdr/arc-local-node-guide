Bu rehber, circlefin/arc-node deposundaki make testnet akışını takip eder. Tek komutla ayağa kalkan yerel bir Arc ağı kurarsın — internet bağlantısı olmadan, gerçek konsensüs ile. macOS ve Linux'ta da aynı adımlar geçerli; sadece WSL bölümünü atla.

This guide follows the make testnet workflow from circlefin/arc-node. One command gives you a local Arc network with real consensus, no public testnet needed. The same steps work on macOS and Linux — just skip the WSL section.

01GereksinimlerRequirements

Donanım: 8+ CPU çekirdeği, 16 GB RAM ve en az 80 GB boş disk. Bu son madde şaka değil: Rust derleme klasörü (target/) tek başına ~35 GB, Docker imajları + build cache ~14 GB yer kaplıyor.

Hardware: 8+ CPU cores, 16 GB RAM, and at least 80 GB free disk. That last one is not a formality: the Rust build directory (target/) alone reaches ~35 GB, with another ~14 GB in Docker images and build cache.

Hardhat yalnızca çift Node.js sürümlerini destekler (20.x, 22.x). 23.x veya 25.x ile derleme kırılır. Foundry sürümü de depodaki .foundry-version dosyasına sabitlenmiştir — farklı sürüm make tarafından reddedilir.

Hardhat only supports even Node.js versions (20.x, 22.x) — 23.x or 25.x will break the build. The Foundry version is pinned by .foundry-version in the repo, and make rejects anything else.

02Windows'taysan: önce WSL2On Windows: install WSL2 first

PowerShell'i yönetici olarak aç ve şunu çalıştır:

Open PowerShell as Administrator and run:

powershell
wsl --install -d Ubuntu

Bilgisayarı yeniden başlat, Ubuntu'yu aç, kullanıcı adı ve şifre belirle. Bundan sonraki tüm komutlar Ubuntu terminalinin içinde çalışır — PowerShell'de değil. Ayrıntı: Microsoft WSL kurulum belgeleri.

Reboot, open Ubuntu, and set a username and password. Every command from here on runs inside the Ubuntu terminal, not PowerShell. Details: Microsoft's WSL install docs.

WSL'in sanal diski (ext4.vhdx) C: sürücünde durur, büyür ve kendi kendine küçülmez. C:'de bol yer bırak.

WSL's virtual disk (ext4.vhdx) lives on your C: drive, grows, and never shrinks on its own. Leave it room.

03Bağımlılıkları kurInstall the dependencies

Hepsi Ubuntu terminalinin içinde, sırayla.

All of this runs inside the Ubuntu terminal, in order.

3.1 — Sistem paketleri

3.1 — System packages

bash
sudo apt-get update && sudo apt-get install -y build-essential pkg-config libclang-dev zlib1g-dev libssl-dev git curl unzip protobuf-compiler

3.2 — Docker (WSL'in içine; Docker Desktop gerekmez)

3.2 — Docker (inside WSL; no Docker Desktop needed)

bash
curl -fsSL https://get.docker.com | sudo sh
sudo usermod -aG docker $USER

Terminali kapat, yeniden aç, sonra servisi başlat:

Close the terminal, reopen it, then start the service:

bash
sudo service docker start && docker ps

WSL'de systemd varsayılan olarak kapalı — bu yüzden her yeniden başlatmadan sonra Docker'ı sudo service docker start ile elle başlatırsın.

systemd is off by default in WSL, so you start Docker manually with sudo service docker start after each reboot.

3.3 — Rust

3.3 — Rust

bash
curl --proto '=https' --tlsv1.2 -sSf https://sh.rustup.rs | sh
source "$HOME/.cargo/env" && rustc --version

Depodaki rust-toolchain.toml doğru sürümü (1.93.0) otomatik seçer, elle uğraşman gerekmez.

The repo's rust-toolchain.toml pins the right toolchain (1.93.0) for you — nothing to select by hand.

3.4 — Node.js 22

3.4 — Node.js 22

bash
curl -fsSL https://deb.nodesource.com/setup_22.x | sudo -E bash - && sudo apt-get install -y nodejs
node --version

3.5 — Foundry (sürüm sabit!)

3.5 — Foundry (pinned version!)

bash
curl -L https://foundry.paradigm.xyz | bash
source ~/.bashrc && foundryup -i v1.4.4 && forge --version

3.6 — Buf

3.6 — Buf

bash
sudo curl -sSL "https://github.com/bufbuild/buf/releases/latest/download/buf-$(uname -s)-$(uname -m)" -o /usr/local/bin/buf && sudo chmod +x /usr/local/bin/buf

04Depoyu klonlaClone the repo

bash
git clone https://github.com/circlefin/arc-node.git && cd arc-node
git submodule update --init --recursive && npm install

Submodule adımını atlama — kontratlar orada. Belirli bir sürümü çalıştırmak için (biz v0.8.0 "Zero8" kullanıyoruz):

Don't skip the submodule step — the contracts live there. To run a specific release (we run v0.8.0 "Zero8"):

bash
git checkout v0.8.0

05Ağı başlatStart the network

bash
make testnet

Bu tek komut sırayla: kontratları derler → genesis üretir → Docker imajlarını build eder → 5 validator + 1 full node + Blockscout + Prometheus + Grafana'yı ayağa kaldırır.

That single command compiles the contracts, generates genesis, builds the Docker images, and brings up 5 validators, 1 full node, Blockscout, Prometheus and Grafana.

İlk çalıştırma uzun sürer — Rust derlemesi yüzünden makineye göre yaklaşık 30–60 dakika. Kahve molası. Sonraki başlatmalar birkaç dakika sürer.

The first run takes a while — roughly 30–60 minutes depending on your machine, almost all of it the Rust build. Later starts take a few minutes.

Başarılı olduğunda terminalde şunu görürsün:

When it works, the terminal ends with:

output
✅ Nodes have reached height 1 nodes=validator1, validator2, validator3, validator4, validator5, full1
✅ Testnet started

07Çalıştığını doğrulaVerify it's alive

bash
cast block-number --rpc-url http://localhost:8545
cast chain-id --rpc-url http://localhost:8545

Blok numarası her sorguda artıyor ve chain id 1337 dönüyorsa ağ üretimde demektir. cast yoksa aynı şeyi curl ile yapabilirsin:

If the block number climbs between calls and the chain id comes back 1337, your network is producing blocks. Without cast, curl does the same job:

bash
curl -s -X POST -H 'Content-Type: application/json' --data '{"jsonrpc":"2.0","method":"eth_blockNumber","params":[],"id":1}' http://localhost:8545

10Sorun gidermeTroubleshooting

Aşağıdakilerin hepsi bizim başımıza geldi — özellikle v0.7.3'ten v0.8.0'a yükseltirken.

Every one of these actually happened to us, mostly while upgrading from v0.7.3 to v0.8.0.

unexpected argument '--arc.denylist.enabled'

Eski .quake cache'i, kaldırılmış CLI flag'lerini yeni sürüme taşıyor. Cache'i tamamen sil:

A stale .quake cache is carrying removed CLI flags into the new version. Wipe it completely:

bash
rm -rf .quake/ && make testnet
EL has blocks but CL has no committed state

Execution layer'da eski zincir verisi var, consensus ise sıfırdan genesis bekliyor. İkisi birlikte sıfırlanmalı:

The execution layer still has old chain data while consensus expects a fresh genesis. The two must be reset together:

bash
make testnet-clean && make testnet
Pool overlaps with other one on this address space

Çok sayıda up/down döngüsünden sonra Docker'ın ağ veritabanı bozulmuş olabilir:

After many up/down cycles, Docker's internal network database can get corrupted:

bash
sudo service docker stop
sudo rm -rf /var/lib/docker/network/files/local-kv.db
sudo service docker start

Ayrıca Docker'a daha geniş subnet havuzu ver — /etc/docker/daemon.json:

Also give Docker a wider subnet pool in /etc/docker/daemon.json:

json
{
  "default-address-pools": [
    {"base": "172.80.0.0/16", "size": 24},
    {"base": "172.90.0.0/16", "size": 24}
  ]
}
Read-only file system · disk doldu (Windows + WSL)disk full (Windows + WSL)

WSL'in ext4.vhdx dosyası büyümüş ama içerideki alan boşalınca Windows'a geri dönmüyor. Önce içeriyi temizle:

WSL's ext4.vhdx grew, and freeing space inside it doesn't return that space to Windows. Clean up inside first:

bash
cargo clean
docker system prune -a --volumes -f

Sonra Windows'ta (yönetici PowerShell) diski gerçekten küçült:

Then actually shrink the disk from Windows (Admin PowerShell):

powershell
wsl --shutdown
diskpart
# select vdisk file="C:\Users\<user>\AppData\Local\Packages\...\ext4.vhdx"
# compact vdisk
getpwuid failed · WSL çöktücrashed

Genelde disk sıkışmasının belirtisidir. Yönetici PowerShell'de wsl --shutdown çalıştır, Ubuntu'yu yeniden aç, sonra disk alanını kontrol et.

Usually a symptom of the disk problem above. Run wsl --shutdown in Admin PowerShell, reopen Ubuntu, then check your free space.
